## Summary

Use the Robotics module description to explain how tote tasks flow from the Sorter Sweeper module to the Robotics module and then to Geek+ for AGV execution. Recognize the Robotics module’s documented Geek+ command types used during tote task execution.

## When To Use

When L1 support needs to interpret what the Robotics module is responsible for during tote task execution (state-machine role, handoff from Sorter Sweeper, and the set of Geek+ AGV command types) to guide troubleshooting discussions.

## Do Not Use For

* Do not use this procedure as a substitute for deeper diagnostics when live system behavior cannot be reconciled with the documented handoff (Sorter Sweeper → Robotics → Geek+).

## Procedure Steps

### Step 1 — Recall the Robotics module responsibility as the AGV state machine

**Responsible role:** L1_support

**Instruction:**
In your troubleshooting discussion, treat the Robotics module as the AGV state machine and use that framing when interpreting tote task execution behavior.

**Expected result:**
You can accurately state that the Robotics module “acts as the state machine for AGVs.”

---

### Step 2 — Confirm the handoff: Robotics receives tote tasks from Sorter Sweeper

**Responsible role:** L1_support

**Instruction:**
In your troubleshooting discussion, describe the handoff as: Sorter Sweeper provides tote tasks to the Robotics module, and the Robotics module then generates commands for Geek+ to execute.

**Expected result:**
You can accurately state that the Robotics module “receives tote tasks from the Sorter Sweeper module.”

---

### Step 3 — Identify the documented Geek+ AGV command types generated by Robotics

**Responsible role:** L1_support

**Instruction:**
Use the Robotics module command list as the canonical set of Geek+ AGV command types for tote execution discussions.

**Expected result:**
You can list the documented command types: Induct tote, Remove tote, Empty go to, Pickup tote, Move tote, Drop off tote, Cancel Request, Go Charge.

---

### Step 4 — Map tote-task execution stages to the expected Robotics→Geek+ command types during troubleshooting discussions

**Responsible role:** L1_support

**Instruction:**
When discussing a tote-task execution issue, use the documented command list to state what the Robotics module would be expected to request from Geek+ for the relevant task stage (induct/remove/empty/pickup/move/drop/cancel/charge).

**Expected result:**
You can connect the tote-task stage to the corresponding documented command type from the Robotics module list.

**Stop or Escalate If:**

* If the live system behavior cannot be reconciled with the documented command types or the expected handoff (Sorter Sweeper → Robotics → Geek+), escalate to deeper system diagnostics beyond this training-derived interpretation.

---

## Success Criteria

* Support can accurately describe that the Robotics module acts as the AGV state machine.
* Support can accurately describe that the Robotics module receives tote tasks from the Sorter Sweeper module.
* Support can name the documented Geek+ AGV command types used for tote execution: Induct tote, Remove tote, Empty go to, Pickup tote, Move tote, Drop off tote, Cancel Request, Go Charge.
* During troubleshooting discussions, support can map a tote-task stage to the expected command type vocabulary.

## Failure Conditions

* AGV state-machine responsibility is attributed to the wrong component.
* Task-flow direction is incorrect or missing (Sorter Sweeper → Robotics → Geek+).
* Command names used in discussion do not match the documented Robotics module command list.
* Live behavior cannot be reconciled with the documented handoff/command vocabulary.

## Escalation Guidance

* Escalate to deeper system diagnostics beyond this training-derived interpretation if live system behavior cannot be reconciled with the documented command types or the expected handoff (Sorter Sweeper → Robotics → Geek+).
