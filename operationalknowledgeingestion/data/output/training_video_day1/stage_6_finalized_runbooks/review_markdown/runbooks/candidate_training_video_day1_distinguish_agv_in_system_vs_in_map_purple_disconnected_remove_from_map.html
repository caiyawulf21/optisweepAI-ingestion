Summary

Use the Map Monitor’s counts and AGV/map association behavior to explain why an AGV can be present in RMS/system counts but not appear as an active map member—specifically the “purple AGV” disconnected case (turned off but still associated to the map) versus the “removed from the map” case (removed from map association but still part of the system).

When To Use

When you need to interpret Map Monitor counts and map display for AGVs that are associated with RMS/system but are not added/associated with the active map view—especially to distinguish “purple AGV” disconnected (turned off but still in the map) from “removed from the map” (no longer associated with the map view).

Procedure Steps

Step 1 — On the Map Monitor, identify the two related counts: AGVs “in the map” vs AGVs “in the system but not added to the map.”

Responsible role: L1_support

Instruction:

Open the Map Monitor and locate the count panel that shows (a) AGVs “in the map” and (b) AGVs “in the system but not added to the map.”

Expected result:

You can see two distinct counts: one for AGVs in the map (example shown: 57) and one for AGVs in the system but not added to the map (example shown: 34).

Stop or Escalate If:

  • If you cannot find the counts or the UI does not match the described Map Monitor count panel, escalate for deeper troubleshooting of map association/state.

Step 2 — Interpret the “purple AGV” case: turned off but not removed from the map.

Responsible role: L1_support

Instruction:

On the map, look for AGVs displayed as “purple” (robot disconnected). Then interpret that behavior as: the AGV was turned off but not removed from the map association.

Expected result:

You can explain that a turned-off AGV still appears on the map as a “purple AGV,” meaning it is disconnected and still in the map.

Stop or Escalate If:

  • If the observed map behavior does not match the purple/disconnected definition (turned off but still in the map), escalate for deeper troubleshooting of map association/state.

Step 3 — Interpret the “removed from the map” case: removed from map association but still part of the system.

Responsible role: L1_support

Instruction:

When an AGV is no longer associated with the viewed map, interpret that as “removed from the map” while it remains part of the system. Confirm by observing that the AGV no longer appears on the map view you are looking at, even though it can still be counted as part of the system roster.

Expected result:

You can explain that once an AGV is removed from the map, it no longer appears/associates with the map you are viewing, but it is still part of your system.

Stop or Escalate If:

  • If observed map behavior does not match the “removed from the map” definition (no longer associated with the map view but still part of the system), escalate for deeper troubleshooting of map association/state.

Step 4 — Apply the association logic when explaining counts and map state.

Responsible role: L1_support

Instruction:

When asked to explain a mismatch between counts and map display, use the following logic: turning off affects disconnected behavior (purple/disconnected but still in the map), while removing affects map association (no longer associated with the viewed map but still part of the system).

Expected result:

You can correctly explain why an AGV appears as purple/disconnected on the map when turned off but not removed, versus why it disappears from the map when removed while still remaining in the system.

Stop or Escalate If:

  • If the observed map behavior does not match the purple/disconnected vs removed-from-map definitions, escalate for deeper troubleshooting of map association/state.
