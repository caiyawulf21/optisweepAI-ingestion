# Restore pairing/fleet operation when a zone reports it can’t get a pair and the ACB system appears down

## Playbook Header

| Field | Value |
| --- | --- |
| Playbook ID | `playbook_incident_228723_acb_zone_pairing_stoppage_robot_removed` |
| Case ID | `228723` |
| Extraction Mode | `one_playbook_candidate_per_incident` |
| Confidence | `medium` |
| Validation Status | `needs_sme_review` |

## Entry Symptoms

- Site reports the ACB system is down
- A specific zone reports it is unable to get a pair
- AMRs appear to route abnormally (e.g., to the hospital lane) during the pairing failure
- Site reports earlier low-battery AMR activity and/or attempted add/remove of robots

## Affected Systems

- ACB system (as reported by site)
- AMRs / AGVs
- RMS (fleet/robot management UI)
- WCS / OptiSweep backend (via WCS/SSMS read-only diagnostics where available)
